# Hoiko Linux

从 `Hoiko_PPT_v0-beta1/Hoiko.exe` 恢复搜索核心，在 Linux 编译为原生共享库，通过只读游戏内存和虚拟 Xbox 手柄操作 Steam/Proton 下的 PPT2。

当前已在这台机器的 **PPT2 Steam build 15220611** 实机验证：2P 的空 Hold、交换 Hold、旋转、软降和自动换局可用；2026-10-08 最终执行层的 20 次落点与实际棋盘逐块对照全部一致。当前安装的 Steam 版本可直接使用，**不需要降级**。详细结果见 [收尾验收记录](docs/VALIDATION.md)。

## 桌面控制面板

```sh
./hoiko gui
# 不带参数也会打开面板
./hoiko
```

面板采用大字号单栏布局，包含原版基本设置、策略模板、搜索参数、原版设置逆向清单、运行日志和手动按钮。默认速度 10%；通过滑条或键盘输入支持 1–100% 精确调速，运行中无需重启。5% 约每秒 1 个操作，10% 约每秒 2 个操作；游戏重力不变，实际落块速度还取决于动作数量与动画。

“连接手柄”只连接，不自动玩；“开始运行”启用自动操作；“暂停自动”在当前方块完成后暂停且保持手柄；“断开 / 停止”立即请求停止并释放输入。调整面板后可点击“返回游戏窗口”。搜索参数在下次启动时应用。设置自动保存到 `~/.config/hoiko/settings.json`。

应用菜单中可搜索“Hoiko 控制面板”。更新代码后，关闭旧面板再重新打开即可使用新版界面。

### 陪练模式

在面板的“陪练模式”页勾选“启用陪练模式”，选择人类玩家的位置后开始运行。默认关闭，旧设置自动补上关闭状态；关闭时保留原有搜索、操作速度和菜单流程。Bot 仍使用原来的策略，陪练单独控制输入节奏。

以人类玩家已落下方块的最高堆叠高度判断危险，高度上升须稳定 0.15 秒才减速：达到 14 行时，两块之间额外等待 1 秒；达到 17 行时，额外等待最多 2 秒，Bot 持续出块。块内移动、旋转和落块保持用户所选速度，避免逐个动作拖慢导致自然锁定与堆死。Bot 自身堆高达到 17 行时取消额外等待，优先自保。人类降至 10 行及以下并稳定 2 秒后，恢复原节奏。运行中改动速度仍然有效，换局后重新判断。面板显示当前保护状态和块内速度。

消行动画和读取失败不作为危险高度，也不触发暂停；短暂不可读时沿用最近一次有效判断，超过 1 秒没有有效读数时恢复原节奏。陪练只调整两块之间的有上限等待，不会中止正在执行的落块计划。手动暂停、停止按钮与原有游戏状态保护照常工作。

命令行可使用 `./hoiko run --backend gamepad --player 2 --speed 10 --practice --focus`；默认保护 1P，Bot 控制 1P 时默认保护 2P，也可以用 `--practice-player 1` 指定陪练对象。陪练对象必须与 Bot 位置不同。

陪练通过只读棋盘监测和出块减速提供喘息时间。游戏重力与已经发送的垃圾行仍会继续；当前判断未计入尚未落下的垃圾行。原版 EXE、权重和搜索核心保持原样。

陪练已通过自动测试与面板控件/布局检查；本次没有可连接的 PPT2 进程，尚未完成陪练模式的实机验收。

GTK4 界面使用系统 Python 的 PyGObject、GTK4 和 pycairo。本机已安装。原版设置逐项还原与未移植项见 [控制面板逆向清单](docs/UI_REVERSE_ENGINEERING.md)。

## 启动

需要 Linux x86-64、Python 3、CMake、C++17 编译器，以及 Steam/Proton 的 PPT2。正常运行不需要 Windows Hoiko、.NET 或 SCP 驱动。

```sh
git clone https://github.com/Mofusigil/hoiko-linux.git
cd hoiko-linux
./build.sh
./hoiko run --backend gamepad --player 2 --focus --speed 10
```

先在 Steam 启动 PPT2，再启动 Bot，进入本地多人 VS。人类玩家控制 1P，Bot 使用虚拟手柄控制 2P；角色界面会自动导航到原版选择的角色位置，选择 Tetris 和普通 A，并等待实际就绪状态。`--focus` 会将游戏窗口切到前台，维持游戏输入。

Ctrl+C 停止 Bot 并断开虚拟手柄。默认搜索宽度 100、深度 6；测试所用的较轻配置是 `--beam 40 --depth 4`。`--seconds 60` 可限定运行时长。搜索核心目前串行运行。

Bot 仅接入本地离线 Tetris VS；游戏版本由 EXE 的 SHA256 匹配。PPT1 的旧内存布局保留在代码中，但目前没有已验证的 PPT1 版本配置。

## 检查与离线求解

```sh
./hoiko doctor
./hoiko watch --player 2 --seconds 10
./hoiko run --player 2 --dry-run --seconds 10
./hoiko solve examples/empty.json
python3 -m unittest discover -s tests -v
```

当前有 70 项回归测试，包含低堆高消行动画、高堆高持续出块、Bot 自保、恢复和关闭模式兼容检查。真实对局验收前先停止其他 Bot，进入本地双人 Tetris VS，再运行：

```sh
python3 tools/check_live.py --turns 20 --seconds 90
python3 tools/check_live_gui.py
```

两项检查依次运行；赛后由 1P 确认“继续游戏”，游戏暂停时由 1P 恢复。第一项逐次比对实际落点、消行后的棋盘与求解结果；第二项使用临时设置验证面板暂停、手动按键、调速、恢复与断开，完成后释放手柄。记录默认写入 `build/final-check/`。

`doctor` 检查内存读取、帧计数、菜单状态和实际 `uinput` 可用性。`watch` 和 `--dry-run` 只读取状态。离线输入格式见 `examples/empty.json`：棋盘自底向上，每行是 10 位掩码，最左格对应 bit 9；`pieces` 包含当前方块和后续队列，顺序为 `IJLOTSZ`，Hold 值 7 表示为空。

## 输入设备

虚拟手柄需要可以打开 `/dev/uinput`。如果缺少模块，可运行 `sudo modprobe uinput`；同时需要当前桌面用户对该设备有读写权限。请用 `./hoiko doctor` 检查，不必以 root 运行 Bot。内核更新后运行内核与模块不一致会导致 `ENODEV`，重启可解决本次出现的这个问题。

当前前台切换使用 X11/XWayland，已在本机 Wayland 桌面的 Proton 窗口验证。键盘后端 `--backend keyboard --player 1` 是备用方案，尚未实机验证其默认键位和完整菜单流程。可以用 `--keys path.json` 提供键位映射。
